# README — Prototype Testing Guide
**โปรเจกต์:** Design Thinking — ผู้สูงอายุในสวนธนบุรีรมย์
**โซลูชัน:** กระดานบอร์ด (Community Board) ณ จุดรวมพลของสวน

ไฟล์นี้อธิบายว่าผู้ร่วมทำงาน (collaborator) ต้องทำอะไรบ้างภายในแต่ละโฟลเดอร์ของ Prototype แต่ละเวอร์ชัน เพื่อให้ทุกคนเก็บข้อมูลการทดสอบไปในทิศทางเดียวกัน

---

## 📁 โครงสร้างโฟลเดอร์

แยกโฟลเดอร์ตามเวอร์ชันของ Prototype ดังนี้:

```
DTproject/
├── version-1/                 # บอร์ดวัยเก๋าแบบยึดมั่น (Fixed Board)
│   ├── test-script.md
│   ├── storytelling.md
│   └── prototype/
│       └── (รูปภาพ/สื่อของ feature & design แบบ low-fidelity)
│
└── version-2/                 # บอร์ดวัยเก๋าแบบอิสระ (Mobile Board)
    ├── test-script.md
    ├── storytelling.md
    └── prototype/
        └── (รูปภาพ/สื่อของ feature & design แบบ low-fidelity)
```

> แต่ละ version ทำงานแยกกันอย่างอิสระ แต่ใช้โครงสร้างไฟล์และหัวข้อชุดเดียวกัน เพื่อให้เปรียบเทียบผลระหว่างเวอร์ชันได้ง่ายตอนสรุปผล

---

## ✅ Checklist งานที่ต้องทำ (ต่อ 1 เวอร์ชัน)

- [ ] Test Script (Say - Do - Think - Feel)
- [ ] Storytelling (สมมติบทบาทผู้ใช้งาน)
- [ ] Prototype (Feature & Design — แบบทดสอบ/low-quality)

รายละเอียดและตัวอย่างของแต่ละหัวข้ออยู่ด้านล่าง

---

## 1️⃣ Test Script — Say / Do / Think / Feel

**เป้าหมาย:** เก็บปฏิกิริยาจริงของผู้ใช้งานทั้ง "ระหว่าง" และ "หลัง" การทดสอบ Prototype โดยใช้คำถามปลายเปิดเท่านั้น (ห้ามใช้คำถามปิดแบบใช่/ไม่ใช่)

### 📌 ช่วงกำลังทดสอบ Prototype (During Testing)

สังเกตและถามไปพร้อมกับที่ผู้ใช้งานลงมือทำจริง โดยคำถามขั้นตอน 

| มิติ | ตัวอย่างคำถามปลายเปิด |
| :--- | :--- |
| **Say** | ตอนนี้กำลังคิดจะเขียนอะไรลงบอร์ด ลองเล่าให้ฟังหน่อย |
| **Do** | ตอนนี้กำลังทำอะไรอยู่กับบอร์ด ลองเล่าขั้นตอนให้ฟังหน่อย |
| **Think** | ระหว่างที่ลองใช้ มีอะไรที่คุณคิดอยู่ในใจตอนนี้บ้าง |
| **Feel** | ตอนนี้รู้สึกอย่างไรกับสิ่งที่กำลังลองทำอยู่ |

### 📌 ช่วงหลังทดสอบ Prototype (After Testing)
ถามหลังจากผู้ใช้งานลองใช้ครบแล้ว เพื่อให้สะท้อนภาพรวม โดยคำถามขั้นตอน 

| มิติ | ตัวอย่างคำถามปลายเปิด |
| :--- | :--- |
| **Say** | ลองเล่าให้ฟังหน่อยว่าที่ผ่านมาเป็นอย่างไรบ้าง |
| **Do** | มีช่วงไหนที่ทำแล้วติดขัด หรือช่วงไหนที่ทำได้ง่ายเป็นพิเศษ เล่าให้ฟังหน่อย |
| **Think** | หลังจากลองใช้แล้ว คิดว่าบอร์ดนี้ช่วยตอบโจทย์อะไรในชีวิตประจำวันบ้าง |
| **Feel** | ความรู้สึกโดยรวมหลังจากลองใช้เป็นอย่างไรบ้าง |

> 💡 บันทึกคำตอบจริงของผู้ใช้งาน (verbatim) ลงใน `test-script.md` ของแต่ละ version พร้อมระบุว่าเป็นช่วง During หรือ After

## 2️⃣ Storytelling — สมมติบทบาทจากกลุ่มผู้ใช้งาน

**เป้าหมาย:** เล่าเรื่องการใช้งาน Prototype ผ่านมุมมองของ Persona ที่ทีมสร้างไว้ (Persona 1: วัยเก๋าสายสังคม / Persona 2: วัยทำงาน-แม่บ้าน สายฮาร์ดคอร์รักสุขภาพ) แบ่งเป็น 3 ช่วง: **จุดเริ่มต้น → ระหว่างใช้งาน → ผลที่เกิดขึ้น**

> **พร้อมประกอบรูปภาพจากการ genarete image**

### ตัวอย่าง: Persona 1 "วัยเก๋าสายสังคม" ทดสอบ Version 1 (Fixed Board)

**จุดเริ่มต้น**
> ลุงคนหนึ่งเดินออกกำลังกายตอนเช้าตามปกติ แล้วสังเกตเห็นบอร์ดเก่าที่จุดรวมพลถูกปรับปรุงใหม่ มีสีสันและมีช่องแบ่งโซนชัดเจนกว่าเดิม จึงเดินเข้าไปดูใกล้ๆ ด้วยความสงสัย

**ระหว่างใช้งาน**
> ลุงเห็นโซน "หาเพื่อน" มีโพสต์อิทของคนอื่นเขียนว่าหาเพื่อนตีแบดตอนเย็น จึงหยิบปากกาที่แขวนไว้ข้างบอร์ด เขียนโพสต์อิทของตัวเองติดไว้บ้างว่าอยากหาเพื่อนเดินแกว่งแขนตอนเช้า

**ผลที่เกิดขึ้น**
> วันถัดมาลุงกลับมาดูบอร์ดอีกครั้งตามความเคยชิน พบว่ามีคนเขียนตอบกลับนัดเจอกันตอนเช้าวันรุ่งขึ้น ลุงรู้สึกดีใจและตื่นเต้นเล็กน้อยที่มีคนสนใจ ทำให้รู้สึกว่าตัวเองมีตัวตนในสวนแห่งนี้มากขึ้น

### ตัวอย่าง: Persona 2 "วัยทำงาน/แม่บ้าน สายฮาร์ดคอร์" ทดสอบ Version 2 (Mobile Board)

**จุดเริ่มต้น**
> หญิงคนหนึ่งพาหลานมาซ้อมมวยตามปกติ เห็นบอร์ดเคลื่อนที่ถูกย้ายมาตั้งใกล้จุดที่เธอซ้อม จึงหยุดมองระหว่างพักเบรก

**ระหว่างใช้งาน**
> เธอเห็นกล่องรับความคิดเห็นติดอยู่ข้างบอร์ด จึงเขียนข้อเสนอแนะเรื่องอยากให้เพิ่มจุดห้องน้ำใกล้บริเวณที่ซ้อมมวยหยอดลงกล่อง โดยไม่ต้องรอเจอเจ้าหน้าที่สวนโดยตรง

**ผลที่เกิดขึ้น**
> เธอรู้สึกว่าความคิดเห็นของตัวเองมีที่ทาง ถึงแม้จะไม่ได้ใช้บอร์ดเพื่อเข้าสังคมเหมือนกลุ่มอื่น แต่ก็รู้สึกว่าเสียงของตัวเองถูกรับฟัง และเต็มใจจะใช้กล่องนี้ต่อไปหากมีข้อเสนอแนะอื่นๆ

> 💡 เขียน storytelling ของแต่ละ Persona ต่อ 1 version ลงใน `storytelling.md` — ควรมีอย่างน้อย 1 เรื่องต่อ 1 Persona ที่เกี่ยวข้องกับเวอร์ชันนั้น

## 3️⃣ Prototype — Feature & Design (แบบทดสอบ / Low-quality)

**เป้าหมาย:** ทำต้นแบบแบบเร็วและหยาบ (low-fidelity) เพื่อทดสอบแนวคิด ไม่เน้นความสวยงามหรือความสมบูรณ์

### Feature ที่ต้องมีในต้นแบบ
- 💬 พื้นที่แปะโพสต์อิทสำหรับข้อความพูดคุย (เช่น หาเพื่อนออกกำลังกาย)
- 🔍 กฏและขอบเขตการใช้งานอย่างชัดเจน
- 📍 การแบ่งโซนของโพสต์อิท อย่างน้อย 3 โซน:
  - หาเพื่อน
  - กิจกรรม
  - แบ่งปันความรู้
- 📋 กล่องรับข้อคิดเห็นเกี่ยวกับสวนสาธารณะ
- ✏️ เครื่องมือเขียน (ปากกา/โพสต์อิท) ติดตั้งอยู่ ณ จุดบริการ
- 💧  แอลกอฮอล์ล้างมือ

### แนวทาง Design ของแต่ละเวอร์ชัน

| | Version 1 (Fixed Board) | Version 2 (Mobile Board) |
| :--- | :--- | :--- |
| **ลักษณะ** | ยึดติดกับโครงสร้างเดิมของสวน เคลื่อนที่ไม่ได้ | เคลื่อนย้ายได้ ปรับตำแหน่งตามพื้นที่ |
| **วัสดุต้นแบบ (test)** | กระดาษลัง/ฟิวเจอร์บอร์ดติดทับบอร์ดเดิม | กระดาษลัง/ฟิวเจอร์บอร์ดพร้อมขาตั้งแบบง่าย |
| **จุดที่ต้องเก็บข้อมูล** | ความสะดวกในการเข้าถึงจากตำแหน่งเดิม | ความง่ายในการเคลื่อนย้ายและปรับจุดวาง |

> 💡 เก็บรูปถ่ายของต้นแบบจริง (ภาพร่าง/ของจริงแบบ low-quality) ไว้ในโฟลเดอร์ `prototype/` ของแต่ละ version พร้อมคำอธิบายสั้นๆ ว่าแต่ละ feature อยู่ตรงไหนของบอร์ด

---

## 📝 หมายเหตุสำหรับผู้ร่วมทำงาน

- คำถามทุกข้อใน Test Script ต้องเป็น **คำถามปลายเปิด** เท่านั้น (ใช้ "เล่าให้ฟังหน่อย" / "อย่างไรบ้าง" แทนคำถามใช่/ไม่ใช่)
- Storytelling ไม่จำเป็นต้องเป็นเหตุการณ์จริง 100% แต่ต้องอ้างอิงพฤติกรรม/motivation จาก Persona ที่มีอยู่แล้ว
- ถ่ายภาพหรือบันทึกวิดีโอสั้นๆ ระหว่างทดสอบ Prototype ไว้ประกอบ Test Script ได้ จะช่วยให้ทีมเข้าใจบริบทมากขึ้น
